# Vibe MVP Builder

## Манифест Вайб-кодинга
- Работающее > Идеальное
- Задеплоенное > Локальное
- Готовое > Элегантное
- Фидбек юзеров > Твои предположения

## Протокол сессии

### Минуты 0–5: Определи ГЛАВНУЮ вещь
Напиши одно предложение: "Пользователи могут [сделать X] и получить [результат Y]."
Если не можешь уложиться в одно предложение — ты строишь слишком много.

### Минуты 5–15: Выбери самый 'тупой' стек, который работает
- Нужен веб? → Next.js + Vercel (деплой без конфигов)
- Нужна база? → Supabase (бесплатный план, мгновенный старт)
- Нужна авторизация? → Clerk (внедряется за 5 минут)
- Нужны платежи? → Stripe Checkout (копипаст интеграции)
- Нужен ИИ? → Прямой вызов OpenAI API (забудь про LangChain на этапе MVP)

### Минуты 15 – Финал: Строй в этом порядке
1. Ядро продукта (та самая вещь из шага 0-5)
2. Способ сохранить результат
3. Способ дать доступ другому человеку
4. Деплой
5. СТОП

## Чего НЕ делать (Анти-паттерны)
- ❌ Писать свою систему авторизации
- ❌ Делать админку до того, как появились юзеры
- ❌ Оптимизировать запросы к БД до того, как там появились данные
- ❌ Писать тесты до того, как фича вообще заработала
- ❌ Выбирать микросервисную архитектуру
- ❌ "Я просто добавлю еще вот эту одну фичу в начале"

## Определение готовности
MVP готов, когда:
- [ ] Незнакомец может им воспользоваться без твоих подсказок
- [ ] У него есть публичный URL
- [ ] Он делает ту самую ГЛАВНУЮ вещь
- [ ] Ты можешь показать его кому-то за 30 секунд

## После запуска
1. Кинь ссылку в 3 разных места (соцсети, сообщества)
2. Попроси 5 человек потыкать его и просто смотри за ними (молчи!)
3. Запиши первые 3 вещи, на которых они запнулись
4. Исправь ТОЛЬКО эти 3 вещи
5. Повтори
