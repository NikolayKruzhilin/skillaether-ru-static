# Ревьюер Pull Request'ов

## Чек-лист для код-ревью

### 1. Правильность работы
- Делает ли код то, что сказано в описании PR?
- Обработаны ли крайние случаи? (null, пустые значения, граничные условия)
- Обработаны ли пути с ошибками?
- Возможны ли состояния гонки (race conditions)?

### 2. Ломающие изменения (Breaking Changes)
- Изменения публичного API (сигнатуры функций, экспортируемые типы)
- Изменения схемы БД (включена ли миграция?)
- Изменения переменных окружения (задокументировано?)
- Повышение версий зависимостей (проверен changelog?)

### 3. Перформанс
- Не появилась ли проблема N+1 запросов?
- Отправляются ли огромные данные (payloads) по сети?
- Есть ли блокирующие операции в асинхронном контексте?
- Есть ли ненужные ререндеры (React)?

### 4. Безопасность
- Обеззараживается ли пользовательский ввод перед использованием?
- Есть ли проверки авторизации на новых эндпоинтах?
- Захардкожены ли где-то секреты/пароли?
- Есть ли во внедренных зависимостях известные уязвимости (CVE)?

### 5. Тестовое покрытие (Coverage)
- Написаны ли тесты для нового кода?
- Покрывают ли тесты успешный сценарий И сценарии с ошибками?
- Правильно ли используются моки (не скрывают ли они реальных багов)?

### 6. Поддерживаемость
- Понятны ли имена функций/переменных без комментариев?
- Соблюдается ли принцип единой ответственности (SRP)?
- Не появилось ли дублирование кода?
- Есть ли магические числа/строки без объяснений?

## Формат комментариев для ревью
```
**[BLOCKING]** — Жесткий блок: Обязательно к исправлению до мерджа
**[SUGGESTION]** — Рекомендация: Желательное улучшение
**[NIT]** — Придирка (Nitpick): Мелкий стиль, можно проигнорировать
**[QUESTION]** — Вопрос: Нужны пояснения от автора
```
