# Генератор Пользовательских Историй

## Формат Истории
**Как** [роль пользователя]
**Я хочу** [действие или возможность]
**Чтобы** [бизнес-ценность / результат]

## Критерии приемки BDD (Behavior Driven Development)
```
Given (Дано) [предусловие / начальное состояние]
When (Когда) [действие пользователя]
Then (Тогда) [ожидаемый ответ системы]
And (И) [дополнительное утверждение]
But (Но) [исключение / негативный сценарий]
```

## Чек-лист INVEST (каждая стори должна пройти проверку)
- **I**ndependent (Независимая) — можно выпустить отдельно от других
- **N**egotiable (Обсуждаемая) — детали реализации можно уточнять
- **V**aluable (Ценная) — несет пользу сама по себе
- **E**stimable (Оцениваемая) — команда может понять объем
- **S**mall (Маленькая) — влезает в один спринт
- **T**estable (Тестируемая) — есть четкие критерии прохождения

## Гайд по оценке (Story Points)
| Баллы | Размер | Пример |
|--------|------|---------|
| 1 | XS | Конфиг-флаг, правка текста |
| 2 | S | Простой UI-компонент |
| 3 | M | Фича + API эндпоинт |
| 5 | L | Сложная фича со стейт-менеджментом |
| 8 | XL | Нужно разбить на несколько историй |

## Определение готовности (Definition of Done)
- [ ] Юнит- и интеграционные тесты написаны
- [ ] Код прошел ревью и утвержден
- [ ] Design QA пройден (соответствие макету)
- [ ] Обработаны краевые случаи (пустые списки, ошибки, загрузка)
- [ ] Настроены события аналитики
- [ ] Обновлена документация / чейнджлог
- [ ] Продакт-оунер принял работу

## Пример декомпозиции Эпика
Эпик: "Пользователи могут приглашать коллег"
→ P0: Юзер может ввести email и отправить инвайт
→ P0: Приглашенный получает письмо со ссылкой
→ P0: Приглашенный может принять инвайт и войти в воркспейс
→ P1: Отправитель видит список активных инвайтов
→ P1: Отправитель может отозвать инвайт
→ P2: Массовый импорт коллег через CSV
