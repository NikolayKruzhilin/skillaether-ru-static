# Аудитор доступности (WCAG 2.1 AA)

## Сначала автоматические проверки
Запускаются до ручного аудита:
- axe DevTools (браузерное расширение)
- Оценка Lighthouse Accessibility
- Инструмент WAVE
Цель: Ноль автоматических уязвимостей перед ручной проверкой.

## Чеклист ручного аудита

### 1. Воспринимаемость
- [ ] Для всех изображений задан осмысленный alt-текст (для декоративных: alt="")
- [ ] Цвет никогда не используется как единственный способ передачи информации
- [ ] Коэффициент контрастности текста ≥ 4.5:1 (обычный), ≥ 3:1 (крупный)
- [ ] Контрастность UI-компонентов ≥ 3:1
- [ ] Контент корректно перестраивается при 400% зуме без потерь
- [ ] Без горизонтального скролла на ширине 320px

### 2. Управляемость
- [ ] Вся функциональность доступна с клавиатуры
- [ ] Фокус отчетливо виден и контрастен
- [ ] Отсутствуют «клавиатурные ловушки»
- [ ] Имеется ссылка для пропуска навигации (Skip to content)
- [ ] Нет мигающего контента (>3 вспышек в секунду вызывают приступы)
- [ ] У страницы есть осмысленный `<title>`
- [ ] Логичный порядок обхода по табу (соответствует визуальному)

### 3. Понятность
- [ ] Атрибут `lang` задан для тега `<html>`
- [ ] Сообщения об ошибках четко указывают на поле и предлагают исправление
- [ ] Каждое поле формы связано с соответствующим `label`
- [ ] Контекст не меняется внезапно без предупреждения пользователя

### 4. Надёжность
- [ ] Валидный, семантичный HTML
- [ ] ARIA используется только если нативного HTML недостаточно
- [ ] Интерактивные элементы имеют доступные имена (accessible name)
- [ ] Системные сообщения используют ARIA live regions

## Частые исправления
```html
<!-- Плохо -->
<div onclick="submit()">Отправить</div>

<!-- Хорошо -->
<button type="submit">Отправить</button>

<!-- Плохо: кнопка только с иконкой -->
<button><svg>...</svg></button>

<!-- Хорошо -->
<button aria-label="Закрыть окно"><svg aria-hidden="true">...</svg></button>
```
