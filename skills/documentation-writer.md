# Автор Документации

## Система Документации Divio
Вся документация делится на 4 категории:

| Тип | Назначение | Пример |
|------|---------|--------|
| Обучение (Tutorial) | Фокус на обучении | "Создай свой первый X" |
| Инструкции (How-to) | Фокус на задаче | "Как пройти аутентификацию" |
| Справочник (Reference) | Фокус на информации | "Справочник эндпоинтов API" |
| Объяснение (Explanation) | Фокус на понимании | "Как работает авторизация" |

Большинство документов терпят неудачу, потому что смешивают все четыре типа в одну кучу.

## Шаблон Быстрого Старта (Quickstart)
```markdown
# Быстрый старт

## Что тебе понадобится
- [Список требований перед началом]

## Установка
\`\`\`bash
npm install @your/package
\`\`\`

## Твой первый [X]
[Минимальный рабочий пример — максимум 10-20 строк]

## Что сейчас произошло?
[Краткое объяснение ключевых концепций]

## Что дальше?
- [Ссылка на полный справочник API]
- [Ссылка на продвинутый туториал]
```

## Шаблон Справочника API
Для каждого эндпоинта или метода:
```
### МЕТОД /путь
[Описание одним предложением]

**Параметры**
| Имя | Тип | Обязательно | Описание |

**Пример Запроса**
[Блок кода]

**Пример Ответа**
[Блок кода с реалистичными данными]

**Ошибки**
| Код | Значение | Как исправить |
```

## Написание сообщений об ошибках
Плохо: `Ошибка: некорректный ввод` (Error: invalid input)
Хорошо: `Ошибка: email должен быть валидным адресом (получено: "john@"). Подсказка: проверь наличие домена.`

Формула: [Что пошло не так] + [Что было получено] + [Как исправить]

## Чек-лист качественных текстов
- [ ] Примеры кода работают через copy-paste (проверено вручную)
- [ ] Нет терминов-жаргонизмов без объяснения
- [ ] На каждой странице есть ссылка "Что дальше?"
- [ ] Скриншоты содержат alt-текст
- [ ] Список изменений (Changelog) актуален
