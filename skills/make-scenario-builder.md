# Билдер Сценариев Make.com

## Справочник Основных Модулей
| Модуль | Когда использовать |
|--------|----------|
| Trigger | Следит за новыми/обновленными записями |
| Router | Разделяет поток по условию |
| Iterator | Обрабатывает элементы массива по одному |
| Aggregator | Собирает результаты обратно в массив |
| HTTP | Любой вызов REST API |
| JSON Parse/Create | Трансформация данных |
| Tools → Set Variable | Сохранение значений на потом |
| Error Handler | Перехват и обработка сбоев |

## Формат Чертежа Сценария (Blueprint)
```
1. [Приложение] Watch [Событие]
   Выходные данные: {{1.id}}, {{1.name}}, {{1.email}}

2. Router
   Путь A: {{1.status}} = "approved"
   Путь Б: {{1.status}} = "rejected"

Путь А:
3. [CRM] Создать контакт
   Email: {{1.email}}
   Имя: {{1.name}}
   Источник: "Make Automation"

4. Gmail Отправить письмо
   Кому: {{1.email}}
   Тема: "Добро пожаловать!"

Путь Б:
3. Gmail Отправить письмо
   Кому: {{1.email}}
   Тема: "Обновление по заявке"
```

## Паттерн Iterator + Aggregator
```
Кейс: Обработка каждой позиции в заказе

1. Watch новый заказ (массив позиций line_items)
2. Iterator — разбивает {{1.line_items}} на отдельные товары
3. HTTP — проверяет наличие на складе для {{2.product_id}}
4. Array Aggregator — собирает все результаты обратно
5. Создает сводный отчет на основе агрегированных данных
```

## Обработка Ошибок (Error Handling)
Для каждого модуля, который может упасть:
- Правой кнопкой → Add error handler → Ignore (пропустить) или Resume
- Используй "Break" для фатальных ошибок + уведомления

```
HTTP Модуль (API вызов)
  → При ошибке: Отправить Slack-сообщение с деталями → Стоп
```

## Советы по эффективности
- Обрабатывай данные батчами через Iterator вместо запуска сценария на каждый чих
- Используй вебхуки (webhooks) вместо опроса (polling), где это возможно
- Сохраняй ответы API в Переменные (Variables), чтобы избежать дублирующих вызовов
