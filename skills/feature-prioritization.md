# Фреймворк Приоритезации Фич

## Скоринг по RICE
RICE Score = (Reach × Impact × Confidence) / Effort

| Фактор | Определение | Шкала |
|--------|-----------|-------|
| Reach (Охват) | Затронутые пользователи за квартал | # пользователей |
| Impact (Влияние) | Эффект на цель в случае успеха | 0.25 / 0.5 / 1 / 2 / 3 |
| Confidence (Уверенность) | Насколько ты уверен в оценках? | 50% / 80% / 100% |
| Effort (Усилия) | Человеко-месяцы на запуск | Месяцы |

## Шаблон RICE
```
Фича: [Название]
Reach: [N юзеров/квартал]
Impact: [0.25–3]
Confidence: [50/80/100%]
Effort: [чел-месяцы]
RICE Score: ([Reach × Impact × Confidence%]) / Effort
```

## Группировка по MoSCoW
- **Must Have** — без этого продукт бесполезен или релиз заблокирован
- **Should Have** — высокая ценность, делай в следующем спринте, если есть ресурсы
- **Could Have** — было бы неплохо, отложи на будущие кварталы
- **Won't Have** — явно вне рамок этого цикла

Правило: Если всё является «Must Have», значит, ничего не «Must Have».

## Антипаттерны приоритезации, которых нужно избегать
1. **Эффект HiPPO** — побеждает мнение самого высокооплачиваемого человека (Highest Paid Person's Opinion)
2. **Предвзятость новизны** — последняя жалоба клиента диктует содержание спринта
3. **Инфляция усилий** — команды завышают оценки «для страховки»
4. **Инфляция влияния** — каждый оценивает свою фичу на «3» по шкале Impact

## Шаблон коммуникации со стейкхолдерами
"Мы приоритизируем [Фичу А] выше [Фичи Б], потому что:
- RICE score: А=[балл] против Б=[балл]
- А напрямую влияет на [метрику North Star] на [оценочный %]
- Б может подождать до Q[N+1] с минимальным ущербом для пользователей в промежутке"
