# Форматтер Git-коммитов

## Формат
```
<type>(<scope>): <description>

[необязательное тело письма]

[необязательный футер (подвал)]
```

## Типы коммитов (Types)
- feat: Новая фича (повышение MINOR версии)
- fix: Багфикс (повышение PATCH версии)
- docs: Только документация
- style: Форматирование, никаких правок в логике
- refactor: Реструктуризация кода, поведение не меняется
- perf: Улучшение производительности
- test: Добавление или исправление тестов
- chore: Процесс сборки, зависимости
- ci: Конфигурация CI/CD

## Правила
1. Проанализируй diff, чтобы определить тип (type)
2. Определи область (scope) на основе измененных файлов/модулей
3. Описание (description): повелительное наклонение, строчные буквы, без точки в конце
4. Тело (body): объясни ПОЧЕМУ сделано изменение, а не ЧТО (это видно в diff)
5. Футер (footer): укажи BREAKING CHANGE:, если применимо
6. Держи заголовок (subject line) в пределах 72 символов
