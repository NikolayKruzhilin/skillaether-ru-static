# Из Вайрфрейма в Спецификацию (Dev Spec)

## Структура Спецификации экрана

### 1. Обзор экрана
- Название экрана и роут / URL
- Цель (что юзер тут делает)
- Точки входа (откуда юзер пришел)
- Точки выхода (куда пойдет дальше)

### 2. Список компонентов (Inventory)
Перечисли всё, что есть на экране:
```
- PageHeader (заголовок, кнопка 'назад')
- SearchInput (плейсхолдер, кнопка очистки)
- FilterPills (горизонтальный скролл, активное состояние)
- SkillCard × N (картинка, заголовок, бейдж, кнопка действия)
- EmptyState (для пустого списка)
- LoadingState (скелетоны загрузки)
- ErrorState (кнопка повтора)
```

### 3. Состояния взаимодействий
Для каждого интерактивного элемента пропиши:
- Default (обычное)
- Hover / Pressed (наведение/нажатие)
- Focused (выделение с клавиатуры)
- Disabled (заблокировано)
- Loading (загрузка данных)
- Error (ошибка)
- Success/Empty (успех/пусто)

### 4. Адаптивное поведение
| Точка перегиба | Лейаут |
|------------|--------|
| Mobile <640px | 1 колонка, вертикальное меню |
| Tablet 640-1024px | Сетка из 2 колонок |
| Desktop >1024px | Сетка 3-4 колонки, боковая панель |

### 5. Требования к данным
- Какие данные нужны для рендера экрана?
- Необходимые эндпоинты API
- Параметры загрузки / ошибки для каждого источника
- Логика пагинации (бесконечный скролл или кнопка)

### 6. Краевые случаи (Edge Cases)
- Пустой список: нет данных
- Слишком длинный текст: логика сокращения (overflow)
- Много элементов: нужна ли виртуализация?
- Оффлайн-режим
- Ошибки прав доступа (403)
- Медленный интернет: частичная загрузка контента
