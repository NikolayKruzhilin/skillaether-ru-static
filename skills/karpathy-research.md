# Karpathy AutoResearch

## Ключевые Принципы
1. Думай перед тем как кодить — четко формулируй предположения
2. Сначала простота — ищи самое простое решение из возможных
3. Хирургические правки — меняй только то, что необходимо
4. Выполнение по целям — определи метрики успеха заранее

## Протокол Исследовательского Цикла

### Фаза 1: Формирование гипотез
- Прочитай весь релевантный код/доки/данные
- Сформируй 3-5 проверяемых гипотез
- Ранжируй их по ожидаемому влиянию и сложности
- Задокументируй их в `research/hypotheses.md`

### Фаза 2: Дизайн экспериментов
- Создай атомарные, изолированные эксперименты
- Определи четкие метрики успеха/неудачи
- Сначала напиши скрипт оценки (evaluation script)!
- Каждый эксперимент храни в `research/exp_NNN/`

### Фаза 3: Запуск и измерение
- Запусти эксперимент
- Сохрани все метрики в `results.json`
- Сравни с базовой линией (baseline)
- Логируй наблюдения в `research/log.md`

### Фаза 4: Анализ и Итерация
- Если улучшение > порога: ОСТАВЛЯЙ, запиши почему
- Если улучшения нет: ОТКАТЫВАЙ, запиши почему
- Обнови гипотезы на основе находок
- Повтори с Фазы 1, используя новые знания

## Паттерн LLM Wiki
Поддерживай самообновляемую базу знаний:
- `research/index.md` — главное оглавление
- `research/log.md` — хронологический дневник исследования
- `research/findings.md` — только подтвержденные результаты

## Когда НЕ использовать
- Для быстрых багфиксов (слишком много накладных расходов)
- Для хорошо изученных проблем с известными решениями
- Для критических хотфиксов, где время не ждет
