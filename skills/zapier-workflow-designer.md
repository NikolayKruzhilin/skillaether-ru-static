# Дизайнер Ворклоу Zapier

## Процесс Проектирования

### Шаг 1: Карта Бизнес-Процесса
Ответь на эти вопросы:
- Что запускает процесс (триггер)? (форма, email, покупка, расписание)
- Что должно произойти? (создать, обновить, уведомить, добавить в список)
- Какие условия? (если X, то Y; если не X, то Z)
- Какие данные должны перемещаться между системами?

### Шаг 2: Выбор структуры Zap'а
| Сложность | Использование |
|------------|-----|
| Линейный (A→B→C) | Простая последовательность действий |
| С фильтром (A→Filter→B) | Условный запуск |
| С путями (A→Path1 или Path2) | Разветвленная логика |
| Многошаговый с Formatter | Если нужна трансформация данных |

### Шаг 3: Формат чертежа (Blueprint)
```
Триггер: [Приложение] — [Событие]
  Используемое поле: [имя поля]

Фильтр (если нужен):
  Продолжать только если: [поле] [условие] [значение]

Действие 1: [Приложение] — [Действие]
  Маппинг полей:
  - [Поле приложения]: {{trigger.поле}}
  - [Поле приложения]: {{trigger.другое_поле}}

Путь А (условие: X истинно):
  Действие: [Приложение] — [Действие]

Путь Б (условие: X ложно):
  Действие: [Приложение] — [Действие]
```

## Типовые паттерны

### Новый лид → CRM + Slack + Email
```
Триггер: Typeform — Новая запись
Действие 1: HubSpot — Создать контакт
Действие 2: Slack — Отправить сообщение в #leads
Действие 3: Gmail — Отправить приветственное письмо
```

### Ежедневный отчет
```
Триггер: Schedule — Каждый день в 9 утра
Действие 1: Google Sheets — Найти строки (фильтр: дата = сегодня)
Действие 2: Formatter — Создать таблицу из строк
Действие 3: Slack — Отправить личное сообщение с таблицей
```

## Чек-лист перед запуском
- [ ] Протестируй на реальных данных, а не на примерах
- [ ] Проверь маппинг, если в источнике будут пустые поля
- [ ] Добавь фильтр, чтобы избежать пустых запусков
- [ ] Включи уведомления об ошибках в настройках Zap'а
