# Автор PRD (Документа Потребностей Продукта)

## Вводные данные от тебя
1. Название фичи
2. Какую проблему она решает (1-2 предложения)
3. Кто целевой пользователь
4. Метрика успеха (как мы поймем, что это сработало?)
5. Ограничения (технологические, по времени, по бюджету)

## Структура PRD

### Общая информация
- Название фичи
- Автор + дата
- Статус: Черновик / На ревью / Утверждено
- Приоритет: P0 / P1 / P2

### Проблема (Problem Statement)
- Текущая ситуация (что сломано или чего не хватает?)
- Влияние (на кого это влияет и как часто?)
- Доказательства (данные, интервью, тикеты в саппорт)

### Цели
- Главная цель (одним предложением)
- Метрики успеха (измеримые, с целевыми значениями)
- Не-цели (явно пропиши, что этот проект НЕ решает)

### Пользовательские Истории (User Stories)
Формат: Как [тип пользователя], я хочу [действие], чтобы [результат].

Для каждой истории:
- Критерии приемки (Acceptance criteria в формате Given/When/Then)
- Краевые случаи (Edge cases)
- Состояния ошибок

### Технические требования
- Контракты API (эндпоинты, схемы запроса/ответа)
- Изменения в модели данных
- Требования к производительности (latency, throughput)
- Требования к безопасности

### Вне скоупа (Out of Scope)
Прямо выпиши, что НЕ входит в версию v1.
Это так же важно, как и то, что ВХОДИТ.

### Открытые вопросы
Список нерешенных моментов:
- Сам вопрос
- Варианты решений
- Ответственный и дедлайн

### Таймлайн
- Дизайн: X дней
- Разработка: X дней
- QA (тестирование): X дней
- Запуск: целевая дата
